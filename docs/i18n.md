# 다국어 텍스트 관리

게임 안의 모든 문장(대사, 장면 설명, UI, 규칙 설명, 이름)은 코드와 장면 데이터에 직접 쓰지 않고 `locale/` 폴더의 CSV 파일에 둔다. 한국어는 `ko` 열에 있고, 다른 나라 언어는 열을 하나 더해서(`en`, `ja`, `zh_CN` …) 채우면 된다.

## 형식: Godot CSV 번역 파일

```csv
keys,ko
ui.battle.start,전투 시작
story.s01.ki.001,"또야. 요즘은 뭘 만들어도 이렇게 갈라진단 말이지."
```

- 첫 열 이름은 `keys`, 나머지 열 이름은 언어 코드다. Godot가 CSV를 불러와 언어마다 번역 리소스를 만들고, 코드에서는 `tr("ui.battle.start")`로 꺼낸다.
- 쉼표나 줄바꿈이 든 문장은 큰따옴표로 감싼다. 문장 안의 큰따옴표는 `""`로 쓴다.
- 인코딩은 UTF-8.

> [의견] 형식 후보 3가지: ① Godot CSV ② gettext PO ③ 직접 만든 JSON → ①. 스프레드시트(구글 시트, 엑셀)에서 바로 열고 고칠 수 있고, 언어 하나를 열 하나로 더하기만 하면 된다. Godot가 기본으로 불러온다. PO는 번역 도구가 좋지만 혼자 고치기엔 번거롭고, JSON은 불러오는 코드를 따로 짜야 한다. 번역가가 붙어서 문장이 수만 개가 되면 그때 PO로 바꿔도 키는 그대로 쓸 수 있다.

## 파일 나누기

| 파일 | 담는 것 | 키 앞머리 |
|---|---|---|
| `locale/names.csv` | 인물·장소·유닛·속성·마법·보스의 이름 | `name.` |
| `locale/ui.csv` | 메뉴, 버튼, 알림, 전투 화면 글자 | `ui.` |
| `locale/system.csv` | 규칙 설명, 튜토리얼, 도움말, 속성 능력 설명 | `sys.` |
| `locale/story.csv` | 장면 제목·연출 설명·대사 | `story.` |

## 키 이름 규칙

- 소문자와 밑줄, 점으로 나눈다: `<파일>.<묶음>.<항목>`.
- 대사: `story.s<스테이지 두 자리>.<장면>.<번호 세 자리>` 예: `story.s05.jeon.004`. 장면 이름은 `ki`(기) `seung`(승) `jeon`(전) `gyeol`(결) 또는 `q_magic`, `q_root`, `q_word`, `mini` 같은 퀘스트·미니게임 이름.
- 한 번 정한 키는 바꾸지 않는다. 문장을 고칠 때는 값만 고친다. 장면에서 문장을 빼면 키는 지우고, 새 문장은 새 번호를 쓴다.

## 장면 데이터와 문장을 떼어 두기

누가 말하는지, 어떤 순서인지, 어떤 표정·배경·연출인지는 `data/scenes/*.json`에 두고, 거기에는 문장 대신 키만 적는다. 그래서 번역할 때 장면 데이터는 건드리지 않는다.

```json
{
  "id": "s01_ki",
  "stage": 1,
  "beat": "ki",
  "title": "story.s01.ki.title",
  "place": "s01_forge",
  "direction": "story.s01.ki.dir",
  "lines": [
    { "speaker": "blacksmith", "face": "worry", "text": "story.s01.ki.001" },
    { "speaker": "hero", "text": "story.s01.ki.002" }
  ]
}
```

## 문장 쓰기 규칙

- **끼워 넣는 값:** 바뀌는 값은 `{word}`, `{count}`처럼 이름을 붙여 쓰고, 코드에서 `tr(key).format({"word": w})`로 채운다. 문장 조각을 이어 붙이지 않는다. 언어마다 어순이 달라서 조각을 붙이면 번역이 깨진다.
- **영어 학습 단어:** 대사 속 학습 대상 영어 단어(`defect`, `de-`)는 모든 언어에서 영어 그대로 둔다. 번역가가 알아보도록 백틱 없이 쓰되, `locale/README`의 용어 목록에 올린다.
- **어원 풀이:** "de-는 '떨어져'" 처럼 접두사·어근의 뜻을 풀이하는 부분은 언어마다 다시 써야 한다. 이런 문장은 키 끝에 `_etym`을 붙여 번역가가 알아보게 한다(예: `story.s01.q_magic.002_etym`).
- **글자 길이:** 대사 한 칸은 한국어 기준 두 줄(약 40자) 안. 영어는 보통 1.5배 길어지므로 대화창은 넘치면 다음 칸으로 넘기게 만든다.

## 단어 데이터의 뜻

단어장 데이터(`default_words.json`)의 `meaning`, `nuance`, `example.ko`, 어근의 `meaningKo`는 한국어다. 다른 언어로 낼 때는 단어장 데이터를 건드리지 않고 `locale/words/<언어>.json`에 단어 id별 뜻을 따로 둔다(가정). 형식은 그 언어를 낼 때 정한다.

## 글꼴

한국어·일본어·중국어 글자를 모두 담는 글꼴을 기본으로 쓰거나, 언어별 글꼴을 대체 글꼴(fallback)로 묶는다.
